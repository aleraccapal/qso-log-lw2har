ANTES DE USAR LA SINCRONIZACIÓN EN PRODUCCIÓN
1. Crear un proyecto en Google Cloud (un único proyecto para la aplicación).
2. Habilitar Google Sheets API y Google Drive API.
3. Configurar Google Auth Platform > Branding/Audience. Seleccionar audiencia
   Externa. Agregar usuarios de prueba para el modo Testing. Para habilitar más
   usuarios en general, Google puede exigir publicar y verificar la aplicación.
4. Crear cliente OAuth 2.0 de tipo Aplicación web. En Orígenes autorizados de
   JavaScript incluir exactamente: https://aleraccapal.github.io
   NO agregar /qso-log-lw2har/ al origen, ni un URI de redirección.
5. El ID OAuth público ya está incluido en sync-config.js.
   No poner client_secret, contraseña, token de acceso ni API_KEY en GitHub.
6. Subir a GitHub Pages todos los archivos de la carpeta, no el ZIP.
7. En la app Datos > Mi estación ingresar indicativo; elegir Conectar Google,
   autorizar Google Drive y sincronizar. Se crea una planilla independiente
   QSO Log - <SD> en el Drive de esa cuenta de Google.

MODELO DE SINCRONIZACIÓN
- Cada cuenta de Google mantiene sus propias planillas; cada distintiva tiene
  datos locales separados en el dispositivo. La cuenta se vincula al indicativo.
- En Google Sheets, EVENTOS es el historial autoritativo inmutable de cambios
  (incluidos borrados). QSO, RUEDAS y PARTICIPANTES son vistas legibles.
- NO modificar manualmente EVENTOS ni QSO/RUEDAS/PARTICIPANTES en Sheets,
  porque las ediciones directas no se importan y las vistas se regeneran.
- La sincronización se intenta automáticamente después de cambios locales
  mientras la aplicación esté abierta y tenga autorización vigente.
- Sin Internet los cambios quedan guardados localmente.
- Al cerrar completamente la PWA, el token deja de existir; al volver a abrir,
  hay que pulsar Conectar Google para obtener un token nuevo. No se garantiza
  sincronización en segundo plano con la PWA cerrada.
- Resolución básica de ediciones concurrentes: última marca temporal gana.
  Los relojes de teléfono, tableta y computadora deben estar bien ajustados.
  Se recomienda evitar edición simultánea del mismo QSO en dos dispositivos.
- Un borrado se propaga como tombstone. Los archivos JSON se pueden exportar
  como respaldo, incluyendo tombstones para evitar resurrecciones.
